If you remember one thing

PokerKit is the dealer, not the player.

It knows every rule of poker: whose turn it is, what raise is legal, who wins the pot, where the chips go. It never decides what to do. That part is you, or the bot you write. Everything on this page is a consequence of that one sentence.

Section 1 · The map

One library, four jobs

Picture a real card room. PokerKit ships four people you would find there. Every class you will ever import belongs to one of them.

Dealer
Runs one hand from blinds to payout and refuses illegal moves.
state.py · games.py
State, NoLimitTexasHoldem
Judge
Looks at cards and says which hand is stronger.
hands.py · lookups.py
StandardHighHand
Calculator
Turns ranges into combos and estimates equity by simulation.
analysis.py
parse_range, calculate_equities
Scribe
Writes hands down as text and replays them later.
notation.py
HandHistory (.phh)

Line counts from the repo: state.py 6,439 · notation.py 2,720 · games.py 2,442 · hands.py 851 · analysis.py 555. The Dealer is almost half the library, because poker rules have many corner cases (side pots, all-in runouts, stud bring-ins, draw games).

Section 2 · How you talk to the Dealer

Every program is the same four-step loop

1. Creategame(stacks, players) gives you a fresh state: one hand of poker.
→
2. Askstate.actor_index says whose turn. state.can_fold() etc. say what is legal.
→
3. Actfold(), check_or_call(), complete_bet_or_raise_to(x), deal_hole(...)
→
4. Readstate.stacks, state.board_cards, and at the end state.payoffs.

Repeat steps 2 and 3 while state.status:. When status turns False, the hand is over.

What "Automation" means

A hand has many small chores. Each blue pill below is something you must always do. Each grey pill is a chore you can hand to the Dealer by listing it in automations.

post antespost blindsburn carddeal holedeal board fold · check/call · bet/raisediscard (draw games) collect betsshow / muckkill losing handspush chipspull chips

Poker bot? Automate every grey pill. Want to choose the cards (to test one specific spot)? Leave HOLE_DEALING and BOARD_DEALING out, then call deal_hole('AsKs') yourself. Building a real online table? Automate nothing and animate every step.

Section 3 · The rules that trip people up

Five things to remember

Raise TO, never raise BY.

complete_bet_or_raise_to(6) means "my total bet this street becomes 6", not "add 6". One method covers complete, bet and raise.

Index = position, not seat. Heads-up flips it.

With 3+ players: 0 = small blind, 1 = big blind, last = button. With 2 players: 0 = big blind, 1 = button/small blind, so player 1 acts first preflop. Lab 2 shows this.

Every action comes in threes.

verify_folding() raises an error, can_fold() returns True/False, fold() does it. An illegal action raises ValueError and leaves the state untouched.

Cards are plain strings.

'AsKs' is two cards. Ranks 23456789TJQKA, suits cdhs. '??' is an unknown card, handy for hands where you never saw the cards.

Python counts from 0, hand histories from 1.

In code, the first player is 0. In a saved .phh file the same player is p1. Also, board_cards is a list of lists (one list per card slot) because PokerKit supports multiple boards and run-it-twice.

LAB 1

Meet the Judge

5 min

Start with the smallest piece. from_game(hole, board) finds the best 5-card hand, and hands compare like numbers.

lab1.py
from pokerkit import StandardHighHand

mine  = StandardHighHand.from_game('AsKs', 'QsJsTs2c3d')
yours = StandardHighHand.from_game('AhAd', 'QsJsTs2c3d')

print(mine)          # the best 5 cards it found
print(yours)
print(mine > yours)  # compare like numbers

LAB 2

Play one hand with the Dealer

10 min

Heads-up No-Limit Hold'em, blinds 1/2, 200 chips each. We leave dealing out of automations so we pick the cards.

lab2.py
from pokerkit import Automation, NoLimitTexasHoldem

state = NoLimitTexasHoldem.create_state(
    (
        Automation.ANTE_POSTING,
        Automation.BET_COLLECTION,
        Automation.BLIND_OR_STRADDLE_POSTING,
        Automation.CARD_BURNING,
        Automation.HOLE_CARDS_SHOWING_OR_MUCKING,
        Automation.HAND_KILLING,
        Automation.CHIPS_PUSHING,
        Automation.CHIPS_PULLING,
    ),
    True,     # uniform antes?
    0,        # antes
    (1, 2),   # blinds
    2,        # min-bet
    200,      # every stack = 200
    2,        # players
)

state.deal_hole('AsKs')   # player 0
state.deal_hole('7h7d')   # player 1
print('stacks  :', state.stacks)
print('to act  :', state.actor_index)

state.complete_bet_or_raise_to(6)   # player 1 raises TO 6
state.check_or_call()               # player 0 calls
state.deal_board('Qs Js 2c')        # flop

state.check_or_call()               # player 0 checks
state.complete_bet_or_raise_to(8)   # player 1 bets 8
state.fold()                        # player 0 folds

print('running?:', state.status)
print('stacks  :', state.stacks)
print('payoffs :', state.payoffs)

[198, 199] and to act: 1. Heads-up, player 0 is the big blind and player 1 is the button, who posts the small blind and acts first preflop. That is rule 2.

LAB 5

1,000 hands of random bots

10 min

This is where PokerKit earns its place. Automate every chore, write a bot that picks any legal action, and let three of them play. The while state.status loop is the whole engine.

lab5.py
import random
from pokerkit import Automation, NoLimitTexasHoldem

AUTO = (
    Automation.ANTE_POSTING, Automation.BET_COLLECTION,
    Automation.BLIND_OR_STRADDLE_POSTING, Automation.CARD_BURNING,
    Automation.HOLE_DEALING, Automation.BOARD_DEALING,
    Automation.RUNOUT_COUNT_SELECTION,
    Automation.HOLE_CARDS_SHOWING_OR_MUCKING, Automation.HAND_KILLING,
    Automation.CHIPS_PUSHING, Automation.CHIPS_PULLING,
)
game = NoLimitTexasHoldem(AUTO, True, 0, (1, 2), 2)   # a factory

def random_bot(state):
    choices = []
    if state.can_fold():
        choices.append('fold')
    if state.can_check_or_call():
        choices.append('call')
    if state.can_complete_bet_or_raise_to():
        choices.append('raise')
    pick = random.choice(choices)
    if pick == 'fold':
        state.fold()
    elif pick == 'call':
        state.check_or_call()
    else:
        lo = state.min_completion_betting_or_raising_to_amount
        hi = state.max_completion_betting_or_raising_to_amount
        state.complete_bet_or_raise_to(random.randint(lo, hi))

random.seed(1)
totals = [0, 0, 0]
for _ in range(1000):
    state = game(100, 3)            # fresh hand: 3 players, 100 chips
    while state.status:
        random_bot(state)
    assert sum(state.payoffs) == 0
    totals = [t + p for t, p in zip(totals, state.payoffs)]

print('net chips after 1000 hands:', totals)
print('sum:', sum(totals))
Predict firstCould the assert ever fail? What must sum be?
Check yourself

Poker is zero-sum with no rake, so the sum is always 0. If it ever failed you would have found a bug in the Dealer. This check is the cheapest test you can put in any bot project.

net chips after 1000 hands: [692, 3739, -4431]
sum: 0

1,000 full hands ran in under a second. Notice game is created once and called like a function for each new hand: game = the rules, state = one hand.

Try it: write calling_station(state) that always calls when it can, give it seat 0, and keep the random bots in seats 1 and 2. Who wins over 5,000 hands? This is your first bot experiment.

Section 5 · Where it fits

What PokerKit is for, and what it is not

Use it for

  • The environment a poker bot plays inside
  • Checking your own engine's rules against a trusted one
  • Parsing and replaying hand histories
  • Quick equity checks and range math
  • Odd variants: 2-7 triple draw, badugi, stud, short deck, PLO

It is not

  • A solver. It computes no strategy, no GTO, no EV of a decision
  • Fast enough for billions of hands. Pure Python by design
  • A UI. It is a library; you draw the table yourself

Speed, from the project's own benchmark (one core, i7-1255U)

TaskPokerKitCompare
Full hands simulated847 / sfine for testing and replay, slow for CFR on Hold'em
5-card hand evaluations1,016,741 / streys: 3,230,966 / s

Rule of thumb: prototype with PokerKit, and when a solver needs raw speed, keep PokerKit as the referee that checks your fast engine gives the same payoffs.

Section 6 · Read 3

Recall cards: answer out loud, then open

In one sentence, what is PokerKit?

The dealer, not the player. It enforces the rules and moves the chips; it never chooses actions.

Name the four jobs and one class for each.

Dealer (NoLimitTexasHoldem / State), Judge (StandardHighHand), Calculator (calculate_equities), Scribe (HandHistory).

What four steps does every PokerKit program repeat?

Create a state, ask (actor_index, can_*), act, read (stacks, payoffs). Loop while state.status.

Blinds 1/2. Player raises to 6. What do you call?

complete_bet_or_raise_to(6). The amount is the total, not the increment.

Heads-up: who is player 0, and who acts first preflop?

Player 0 is the big blind. Player 1 is the button/small blind and acts first preflop.

What happens when you make an illegal move?

ValueError, and the state does not change. Use can_* to check first.

You want to choose the hole cards yourself. What do you change?

Remove Automation.HOLE_DEALING (and BOARD_DEALING) from the automations, then call deal_hole('AsKs').

Which one-line test catches most engine bugs?

assert sum(state.payoffs) == 0 after every hand (no rake).

What is the difference between game and state?

game holds the rules and blinds; calling game(stacks, players) makes a new state, which is one hand.

In a .phh file, what does p2 cbr 8 mean?

Player 2 (Python index 1) completes, bets or raises to 8.
